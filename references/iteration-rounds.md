# 分阶段迭代

分轮用于尽早淘汰错误，不是把同一套检查重复三遍。

## Round 1：结构

目标：确认方案骨架可继续研究。

- V0 核心字段；
- V1 区域一致性；
- V4 预约密度；
- V11 预订链接。

先修日期、区域、重复序号、缺坐标和错误链接。

## Round 2：时空

目标：确认真实路线与返程安全。

- V0 核心字段；
- V2 通勤粗算；
- V5 返程缓冲；
- V8 路线来源字段；
- V9 时长下限；
- V13 酒店往返。

这一轮必须拿到主要移动段的地图查询结果，不能靠“看起来很近”。

## Round 3：体验与预算

目标：补齐餐饮、天气和价格证据。

- V0 核心字段；
- V3 餐厅区域；
- V6 天气备选；
- V8 路线字段复核；
- V10 价格溯源。

最后再人工核对用户禁忌（V7）与最新官方通知。

## 全量收口

无论分轮结果如何，交付前都运行：

```bash
python scripts/validate.py trip.json --pretty --fail-on-warn
```

增量修改时可以先跑受影响的轮次，但最终仍需全量收口。
