# 高德地图查询与路线字段

本文描述需要的能力，不绑定具体客户端或工具前缀。以当前环境实际暴露的工具和高德官方接口为准。

## 查询顺序

1. 用文本搜索或地理编码确认 POI；
2. 保存标准名称、地址、经纬度和可回溯标识；
3. 为主要相邻点查询路线；
4. 记录方式、时长、距离和来源；
5. 关键营业/预约信息再用官方渠道确认。

## 坐标格式

POI 推荐使用：

```json
{
  "idx": 1,
  "name": "示例景点",
  "lng": 104.066,
  "lat": 30.658
}
```

数组形式必须是 `[lng, lat]`，不要反转。

## 路线字段

```json
{
  "from_idx": 1,
  "to_idx": 2,
  "mode": "transit",
  "duration_min": 28,
  "distance_m": 6200,
  "description": "地铁 2 号线转公交，约 28 分钟",
  "source": "amap-mcp",
  "source_ref": "origin=104.066,30.658; destination=104.144,30.740"
}
```

`idx = 0` 表示酒店。`duration_min` 应来自路线查询；直线距离粗算只能用于筛错，不能写成 `amap-mcp`。

## 方式选择

结合实际方案比较：

- 步行：距离短、天气与同行人适合；
- 骑行：城市环境允许、无大件行李；
- 公交/地铁：优先比较换乘和步行，不只看总时长；
- 驾车/打车：深夜、行李、多人、无公共交通或用户明确偏好。

不要把固定距离阈值当成唯一决策依据。

## MCP 与 REST

优先使用环境已配置的高德能力。MCP 不可用而用户已有合法 REST Key 时，可调用官方 REST 接口，并把 `source` 写成 `amap-rest-api`。不要把 Key 输出到日志、文件或仓库。

REST 失败时：

- 保留错误并说明未核验；
- 不从直线距离伪造路线结果；
- 不把通用网页估算标成高德来源；
- 可以先交付草案，但严格 V8 会阻止多 POI 日缺路线。

## HTML 地图

地图渲染使用 Web Key，由浏览者在页面输入并只保存在 `localStorage`。服务端 Key 与 Web Key 不应混用，任何 Key 都不得通过 URL 参数传递。
