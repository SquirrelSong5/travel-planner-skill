# 行前复核与安全

## 复核强度

每次调用 Skill 时，用首日日期减去当前日期：

| 距出发 | 必须动作 |
| --- | --- |
| 8 天以上 | 保存现有证据，并为开放、预约、路线、价格、天气和安全设置 `recheck_at` |
| 2–7 天 | 重新核对开放/闭馆、预约状态、主要路线、末班、未付款价格与可售状态 |
| 0–1 天 | 再查逐小时天气、官方预警、临时通知、机场/车站路线和末班信息 |
| 已在途中 | 只处理受影响日期，保留已完成和不相关安排 |

不得把未来自动执行写成已经安排的后台任务。`recheck_at` 是下次调用时的质量门禁；V12 到期后会产生警告，要求先重新查询。

## `rechecks` 记录

每项至少包含：

```json
{
  "item": "景区开放与预约",
  "category": "opening",
  "status": "verified",
  "checked_at": "2026-08-24T15:30:00+08:00",
  "recheck_at": "2026-09-17T09:00:00+08:00",
  "source": "official-site",
  "source_ref": "https://example.org/notice",
  "note": "出发前一天再看临时闭馆"
}
```

类别只用：`opening`、`booking`、`transport`、`price`、`weather`、`safety`。完成复核后更新 `checked_at`、`status` 和结论，不只延后日期。

## Plan B

不要只列一个备选景点。写清：

1. **触发条件**：雨量、预警、闭馆、排队上限、错过班次等可判断条件；
2. **替代安排**：具体地点、时段和餐饮；
3. **调整影响**：取消什么、移动什么、预算与路线如何变化；
4. **路线说明**：替代方案的主要移动顺序。

Plan B 同样要核对坐标、开放和路线。不能用未核验候选替换已核验方案。

## 安全提醒

只输出与当前行程有关、能够采取行动的提醒：

- 天气：高温、暴雨、雷电、冰雪和大风；
- 地形：高海拔、长距离徒步、涉水和夜间山路；
- 交通：末班车、跨城机场、深夜抵达、托运行李和换乘；
- 同行人：老人、儿童、孕妇、行动不便、过敏和饮食禁忌；
- 人流：节假日拥堵、预约密集、返程缓冲。

每条写 `risk`、`action`、`severity`、适用对象和来源。不要制造犯罪风险、医疗结论或未经官方确认的恐慌信息。

## 现场修复顺序

1. 确认用户当前地点、时间、已完成事项和硬性返程；
2. 查询变化的官方事实和剩余路线；
3. 保留返程与安全缓冲；
4. 从已有 Plan B 或同区域候选中替换；
5. 更新 JSON、重跑全量校验并重新生成两种输出。
